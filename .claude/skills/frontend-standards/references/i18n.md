# Internationalisation

English by default, Nepali fully supported: every screen works in both, and the user chooses. Strings live in `packages/i18n` (`en.ts`, `ne.ts`); the type system fails the build if a key is missing in either.

## Rules

- No user-visible string literals in components. Use `t(locale, "feature.key", params)`.
- Keys are grouped by feature (`signIn.title`, `errors.network`). Add the English and Nepali text in the same change; if the Nepali text is not ready, mark the entry `// TODO(ne)` and list it in the report, never leave it empty.
- Never build sentences by concatenation; use parameters (`"Try again after {time}"`).
- Error messages come from the error `code` (`errors.TOO_MANY_CODES`), with a generic fallback; never show the backend's message text (it is English-only and not meant for display).
- Numbers, dates and times through `Intl` with the active locale and the `Asia/Kathmandu` time zone. Bikram Sambat dates when the product asks for them (not built yet).
- Layouts must fit longer Nepali strings; test screens in Nepali.
- Pluralisation through parameters and separate keys until a plural helper is added.
